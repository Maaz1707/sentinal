# Demo Script

## Goal

The demo should feel like a single live emergency briefing, not a collection of disconnected widgets.

## Operator Flow

1. Load the dashboard.
2. Press `START DEMO`.
3. Let the sequence run through plant escalation, plume growth, routing changes, and public messaging.
4. Pause if a judge asks for explanation.
5. Resume the sequence.
6. Restart the demo from the top if needed.

## Suggested Narration

- The plant begins in a nominal state.
- Wind direction changes and the plume starts to affect the sector.
- The scenario escalates and the emergency level rises.
- Protective recommendations and rerouted corridors appear.
- Public alerts are issued and trust drifts downward.
- The timeline grows as the incident unfolds.

## What to Show First

- Top status bar demo controls
- Overview cards
- Situation map
- Decision engine
- Route optimizer
- Alert feed
- Public trust panel

## Judge-Friendly Talking Points

- The interface is coordinated from one simulation clock.
- The demo can be paused, resumed, and restarted without reloading.
- The design is intentionally dense but readable, with live states clearly signaled.
- The system uses static fallback data outside demo mode, so the app remains stable on first load.

## Known Limits

- The scenario is scripted for presentation quality.
- The simulation is illustrative and not authoritative emergency guidance.
